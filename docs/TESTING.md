# M2.5 verification

Verified on 2026-11-14. Results cover Linux-hosted compilation and DOSBox-X's
built-in DOS, not native FreeDOS/MS-DOS or real VGA/mouse/storage hardware.
All fixtures are original, generated by tests; none came from reference editors.

## Automated host checks

`./scripts/test.sh` passes six suites. The existing canvas/cursor, editor and
mock-framebuffer suites retain strict C89/pedantic warnings-as-errors checks:

- Canvas bounds/capacity/clear, all palette indices, line connectivity across
  every slope, bounded four-connected fill, undo/redo/history expiry, gestures,
  every cell at every supported zoom, all palette hit tests and rendering.
- Cursor restoration at all 64000 positions, overlapping moves, grid/partial
  redraws and status redraw ordering.

The file suite links the real file/project/editor/input modules. Only file-I/O
calls are replaced at compile/link time by test wrappers; no fault switches or
hooks are present in PIX86.EXE. It checks:

- Save/load roundtrips at 16×16, 32×32 and 64×64, every palette index 0..255,
  exact indexed pixels, FG/BG, explicit little-endian header bytes and lengths.
- Wrong signature/version/header size/flags/reserved bytes, unsupported dimensions,
  high dimension bytes, wrong 32-bit payload length and trailing bytes. Every
  truncated prefix of a valid 16×16 file is rejected.
- DOS 8.3 paths, default extension, case normalization, drive/root/relative paths,
  invalid names, devices, overlong input, missing directories and non-file targets.
- Existing-file overwrite refusal, approved replacement, temp/backup name
  collisions without truncating unrelated files, and normal recovery cleanup.
- Injected short writes, flush failures and close failures: the old file remains
  readable, current artwork stays dirty, and the saved baseline is not advanced.
- Injected first rename failure, failed installation with successful rollback,
  and failed rollback: the original is restored or retained in BAK, and the new
  complete file is retained in TMP if recovery is needed. Both recovery files
  are parsed and their pixels checked.
- Failed backup deletion after successful installation: returns a success/warning,
  retains a readable old backup, and marks the installed new state saved.
- Read-close failure after decoding: scratch never replaces live artwork.
- Malformed Open preserves live pixels, dimensions, filename, history and dirty
  state. Successful differently sized Open restores FG/BG and resets undo/redo;
  the first undo cannot resurrect the previous project.
- Dirty-state transitions through save, undo, redo, history expiry, same-position
  branch edits, selection changes, view-only changes, failed saves, New and Open.
- Filename editing: selected prefill, replacement, Backspace, Enter/Escape,
  ignoring function keys, and bounded capacity.

The UI suite compiles the real menu/keymap/dialog/input modules against scripted
keyboard/mouse events and checked video/cursor mocks. It checks all headings and
commands, wrapping arrows, F10/Alt/Escape, disabled Frame rows, mouse commands and
outside dismissal, selected prefill, insertion/deletion/navigation/bounds, long
field scrolling, mouse OK/Cancel, confirmation default/approval/cancellation,
New sizes, message recovery paths, and drawing after a consumed held press.
The checked video mock rejects drawing beyond 320x200 or while the cursor is
visible; it uses the shared 6x8 metrics. It also rejects dialog repaints during
idle/release-only polling. UITEST runs these same checks with Watcom 16-bit arithmetic in DOSBox-X.
The host UI and compact-font suites pass AddressSanitizer and UndefinedBehaviorSanitizer.

The file/project suite also passes AddressSanitizer and UndefinedBehaviorSanitizer
with the same fault wrappers. Host tests use `build/iotest/`; test-generated
files are isolated from artwork. Run these fixture-writing tests in a disposable
working directory only.

## Open Watcom and DOS-side checks

`./scripts/build.sh` passes with Open Watcom v2 Linux-hosted 16-bit tools, build
dated 2026-04-04, zero warnings/errors. The application retains `-bt=dos -ms -0`
and a 4096-byte stack. Ordinary modules use `-za -wx -w4 -os`. Only fileio.c uses
`-ze` for CRT exclusive-create/stat/fdopen declarations. The link map uses the
Watcom `lib286/dos` runtime, with no DPMI or extender startup.

- `PIX86.EXE`: 37210 bytes; `file` reports an MS-DOS MZ executable.
- `python3 tests/mzcheck.py`: plain MZ, four relocations, valid entry/stack, no
  extended executable header. Compiler target and DOS execution supply further
  evidence beyond container inspection.
- Link map: 82928 bytes of linked code/data/stack; DGROUP is 49600 bytes
  (including the 4096-byte stack), leaving 15936 bytes below the 64 KiB limit.
  Near code is 33301 bytes plus its startup prefix, also below 64 KiB.
  This excludes PSP/environment and other runtime allocation overhead. The total
  may exceed 64 KiB: small model has separate near code and data segments.
- `./scripts/dostest.sh` builds EDTEST.EXE, IOTEST.EXE, UITEST.EXE and KBDTEST.EXE. All execute successfully
  in DOSBox-X, using Watcom's actual 16-bit int/unsigned arithmetic. The file
  suite, including every injected failure above, prints:
  `PASS: P86 roundtrips, validation, replacement, dirty state and dialogs.`
- EDTEST prints its existing passing tools/zoom/history/gesture result with the
  larger saved-state Editor object. Large mock-framebuffer suites remain host-only.

To repeat the DOS file suite, mount `mnt/`, make a scratch directory, change into
it and run `..\IOTEST > RESULT.TXT`. The suite creates/removes test fixtures in
that directory. Short-write/flush/close errors model disk-full and I/O failures;
a physically full or damaged floppy/disk was **not** tested.

## DOSBox-X UI integration

DOSBox-X 2025.02.01 SDL2, VGA-only, normal 386 core, fixed 40000 cycles, 4 MiB
configured memory; compiled application code remains 16-bit/8086 real mode.
X11 input and screenshot checks run on an isolated Xvfb display with autolock off
and mouse_emulation=never. These are external test tools, not project dependencies.

The earlier file-I/O acceptance run passed (before the menu extension):

1. Draw a 16×16 diagonal sprite with foreground index 255, F2 save as PLAYER
   (default .P86). Independently inspect the 280-byte file's header and all 256
   pixel bytes against the expected pattern.
2. Exit, restart Pix86 and F3 open PLAYER. Screenshot samples match every pixel;
   FG/BG and size restore. Continue drawing in index 141.
3. F2, refuse overwrite: on-disk bytes unchanged and dirty marker retained.
   F2, approve overwrite: expected new pixel/FG persisted, dirty marker clears.
4. Undo from the saved artwork makes it dirty; redo returns it to clean.
5. Shift+F2 Save As COPY: complete contents match PLAYER. Make another edit;
   cancel dirty Exit, New and Open without losing it.
6. Attempt malformed BAD.P86 after confirming Open: prior art and dirty marker
   remain. Dialog dismissal fully repaints the narrow gaps between UI panels.
7. Confirm New, choose 64×64, then Open PLAYER16. Size changes correctly, saved
   artwork returns and history is reset. Undo does not bring back the old canvas.
8. Clean ESC returns to DOS text mode.

The menu/dialog extension was then verified using X11 scripted keyboard/mouse
input against PIX86.EXE in DOSBox-X on an isolated Xvfb display. Screenshots
were inspected at the workspace, menu, filename and confirmation states; saved
files were independently read on the host and pixel bytes checked. Results:

- F10, left/right heading changes, up/down selection, Enter, Escape and Alt+F/R
  operate menus. Frame commands stay disabled and Escape returns to drawing.
  Opening/moving within the same menu paints only the overlay/status; changing
  headings or closing restores the covered workspace.
- Draw and save a 16x16 project; reject overwrite with the initially selected
  Cancel/Enter and confirm the existing bytes are unchanged. Approve overwrite,
  verify changed pixel bytes, undo to dirty and redo to clean.
- Cancel unsaved Exit and New. Approve Open of malformed BAD.P86, acknowledge
  failure, then save current artwork under another name without losing it.
- Use mouse File/Save As, edit the selected filename and click OK. Click outside
  a menu on the canvas, save again, and verify the click did not alter any pixel.
- New 64x64, reopen the saved 16x16 project, draw after returning from dialogs,
  save and verify another pixel changed; clean Escape exits.
- With /NOMOUSE: Alt+R shows disabled Frame, Alt+F and arrows invoke Save,
  Home/Right/End edit the filename cursor, save a 32x32 file, reopen a 16x16
  project and exit using only keyboard input.
- DOSCHECK, DOSCHECK null 16 and DOSCHECK iret 64 each report PASS for restoring
  BIOS mode, active page, cursor shape and cursor position with the extended UI.

After reducing unnecessary menu canvas repaints, a final native build was
rechecked interactively: heading/row changes, mouse outside dismissal, disabled
Frame, drawing, exact saved pixels, reopen and clean exit pass. All five host
suites also pass for the final sources.

Native FreeDOS/MS-DOS, real hardware/storage, power interruption and concurrent
writers remain untested. The save strategy deliberately reports recoverable
BAK/TMP paths after rollback failure; it does not promise power-failure atomicity.

## Manual acceptance checklist

- Repeat the sequence above on each target DOS system and with real mouse drivers.
- Exercise DOS drive-relative/rooted/subdirectory paths, Backspace, Enter, Escape,
  cancellation, invalid names, missing directories and read-only media.
- Fill a disposable test disk, attempt replacement, then verify the old file and
  dirty state. Do not use valuable artwork for media-failure experiments.
- Inspect recovery paths when rename/rollback cannot complete; preserve BAK/TMP.
- Run `scripts/doscheck.sh` and the DOSCHECK mouse/null/iret cases; clean ESC
  should restore the old BIOS mode, active page and cursor shape/position.
- Check /NOMOUSE keyboard file commands and the existing drawing shortcuts.

For menu/dialog keyboard conventions and functional reference provenance, see
[UI_DESIGN.md](UI_DESIGN.md).

The native format, supported path limits, implicit palette and recovery procedure
are specified in [FILE_FORMAT.md](FILE_FORMAT.md). Animation, layers, custom palette
editing and non-native formats remain outside this milestone.


## Compact TDE-inspired redesign verification

The new original 6x8 font suite renders all 95 printable ASCII glyphs through the
actual renderer, checking nonblank glyphs, distinct lowercase, a clear spacing
column, transparent ink, replacement of unsupported bytes, screen-edge clipping
against an unclipped reference image, and INT_MIN/INT_MAX coordinates. No font
fixture or glyph data came from another application.

UI tests additionally cover Ctrl-menu open/toggle from another heading,
BIOS word decoding (ASCII FS, US scan fallback, ISO logical slash, AltGr/plain
slash), extended 00/E0 words, function/Alt/history keys, compact toolbar bounds,
mouse cursor placement in the filename field and idle dialog stability.
KBDTEST injects BIOS words using INT 16h AH=05h and checks actual keyboard_poll
acquisition and nonblocking empty-buffer returns; it passes in DOSBox-X.
EDTEST, IOTEST and UITEST also pass with the compact geometry and font metrics.

Actual X11 Ctrl+backslash input was exercised in DOSBox-X with `KEYB US` and
`KEYB UK`, using `KBDTEST /LOG` to record raw BIOS words:

| DOS layout / physical position | BIOS word | Decoded result |
| --- | --- | --- |
| US backslash, Ctrl held | 2B1C | Menu |
| US backslash, plain | 2B5C | Backslash character |
| UK US-backslash position, Ctrl held | 2B1C | Menu |
| UK US-backslash position, plain | 2B23 | # character |
| UK ISO backslash position, Ctrl held | 561C | Menu |

Both Ctrl+backslash positions open File and a second press closes menus. Arrows,
Enter, Escape and Alt headings remain functional. A UK /NOMOUSE session saves a
32x32 project through the compact filename field and exits with keyboard only.
DOSCHECK, its null-vector 16x16 case and its IRET-vector 64x64 case pass mode,
page, cursor position and shape restoration with the redesigned executable.

The physical-key fallback and AltGr handling are unit tested; real DOS drivers,
other keyboard layouts and actual AltGr hardware are not claimed tested. A BIOS
word does not retain per-event modifier state, so nonstandard layouts/drivers
that do not emit FS can have fallback limits after Ctrl is released. See
UI_DESIGN.md for contracts and the F10/Alt+F alternatives.

Final mouse acceptance uses the compact palette and tool/menu/dialog hit areas.
It independently checks saved pixel bytes after drawing with foreground 255,
mouse File/Save As, outside-menu dismissal, overwrite cancellation/approval,
undo/redo dirty-state transitions, New/Open, and return to drawing/view shortcuts.
Dropdowns are dismissed before commands open modal windows; Save As has its own
title. Screenshots of menus, selected text, confirmations, New and the normal workspace
are visually inspected. Two successive idle filename screenshots are identical:
polling moves/restores only the cursor, without repaint flicker. The application
continues to use 320x200 Mode 13h with the unchanged artwork DAC palette. Native
DOS and physical hardware remain outstanding.
